# RFC-0006: Cognitive Governance — 历史结论修正程序

**Status:** Draft
**Author:** menglingqing（建筑师）；起草协助：Claude Code
**Date:** 2026-08-18

## Summary

RFC 0002/0003 已确立历史结论可被修正的认知原则。本 RFC 不新增认知原则，而规定重要历史结论发生修正时的**治理程序**：显式声明、历史留痕与下游评估。本 RFC 是 OpenDatong 首部认知治理（Cognitive Governance）文书。

This RFC is OpenDatong's first Cognitive Governance document: it governs the procedure of revising established conclusions — declare the revision, preserve the trail, assess downstream impact.

## Motivation

- Agent 与人都有维护自我一致性的倾向：结论一旦出自自己，推翻它就有额外的"认知面子"成本。本程序明确：修正过去的自己是正常治理操作。
- 历史无认知特权，但可能具有资产价值——被推翻的结论及其修正路径常包含重要的失败模式、边界条件与学习信号。64卦案例 v1→v6 的完整版本链从未删除任何一版，被推翻的历史反而成为最有教学价值的资产。
- 立法前反向检验已确认：本候选的"原则"层面已被 RFC 0002/0003 吸收（见"与既有原则的关系"），本 RFC 仅立程序。

## Proposal

### 法域说明

认知宪法（RFC 0002-0005）回答"怎样想才可靠"；认知治理（本 RFC 起）回答"可靠的认知发生变化后，系统如何治理变化"。本程序由全体居民继承，位阶低于宪法原则，不得与原则冲突。

### 修正程序（四条）

1. **修正无惩罚**——当新证据足以改变判断时，修正既有结论是正常治理操作，不要求维护历史一致性的辩护姿态；不维护面子，但维护因果链。
2. **修正须显式声明**——重要修正应明确旧结论、修正依据与新结论，不静默改口，不让旧结论与新结论在记录中并存而不加标注。修正不是产生一个新答案，而是改变一个已有答案的状态。
3. **历史须可追溯**——修正不得造成认知历史断链。旧结论应以适合所属系统的方式保留可追溯状态（当前文档呈现最新版、版本历史保留旧版、认知日志记录变更原因），而非被静默覆盖；法务、安全、隐私等必要删除除外。
4. **下游须评估**——检查可能实质受旧结论影响的已知依赖并处理；无法确认完整影响范围时，显式说明不确定性（呼应 RFC 0004）。

总约束：本程序不制造推翻义务——无新证据时，不以推翻历史为价值（同 RFC 0002）。

### 操作机制：修正四要素

重要修正的声明包含四要素：

- **旧结论**——什么被修正；
- **依据**——为什么（按 RFC 0003）；
- **新结论**——现在采用什么判断；
- **影响面**——哪些下游需要处理（按本程序第 4 条）。

不要求固定章节格式（同 RFC 0004 的去格式化立场）。

### 领域实例化示例

- **幻墨造像（视觉）**：方法论修订时保留旧版全文与改动说明（64卦版本链即此形态）；被推翻的规则标注 superseded 并指向替代规则，格式由知识治理层定义。
- **研究 Agent**：综述修正时显式声明旧结论、新依据与新结论；保留检索历史。
- **产品 Agent**：方向调整时声明被推翻的假设、新判断及受影响的功能决策。
- **Coding Agent**：修复推翻先前诊断时，在提交信息中声明根因修正，不静默覆盖。

### 与既有原则与机制的关系

- RFC 0002 授予推翻的权利与能力（不因出自自身而固守）；RFC 0003 原则 6 规定证据触发（新证据出现时旧结论接受检验）；本 RFC 规定修正的程序。三者合并后，RFC 0002 Open Questions 中的候选原则"允许推翻历史结论"即告吸收关闭。
- knowledge-os 的版本链保留（v1→v6 全部存档）与 learning-log 是本程序在知识层的已落地形态。

### 本程序自身的治理

同 RFC 0002：入宪与修订走 RFC 流程。本程序适用于自身——若未来证据表明本 RFC 应予修正，按本程序执行：显式声明、保留追溯、评估下游。
